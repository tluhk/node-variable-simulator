What this simulator teaches

Use these notes as a companion to the scenarios. The visuals are conceptual: they explain observable JavaScript behavior, not exact V8 memory addresses.

Visual model basics

Call stack

The call stack shows the currently active execution contexts. In this simulator, the newest function call appears above the older caller so you can see which bindings are currently closest to execution.

  • The global frame is the outer script-level context.
  • Function frames appear when a function is called.
  • A frame disappears when that function returns.

Frame types

A frame is a conceptual container for local bindings. The label tells you which scope the bindings belong to: `global frame`, a named function frame such as `update frame`, or a returned closure's active frame such as `inc frame`.

  • Global bindings are visible from top-level code.
  • Function bindings include parameters and local variables.
  • Shadowed names can exist in multiple frames at once.

Heap

The heap represents objects, arrays, functions, and retained closure environments. Variables do not contain these structures directly in the visual model; they hold reference values that point to heap entries.

  • Object and array properties are shown inside heap cards.
  • Multiple bindings can reference the same heap object.
  • Heap entries remain shown while some binding or closure still reaches them.
